## part 1: 抽象

### 一、什么是面向对象
#### (1) 过程式思维回顾

&emsp;&emsp;大家在学习 C++ 的时候编写程序的思维通常是**顺序的**，也就是把要实现的功能拆分成一个个步骤去编写。比如说要找出很多数字中的最大值，可以依次读入数字，与当前最大值比较并更新，循环结束后再输出。
这种思维方式其实没错误，它在小规模的程序里很好用，但程序一大就会出问题：

- 数据到处都是，哪个是用于干什么的很难查找和理解，不便于之后维护。
- 函数之间靠全局变量传数据，牵一发动全身；
- 新加一个功能，要在成百行的代码里翻来翻去地改。

&emsp;&emsp;这对于研究或者编写一个大的代码项目是很致命的。
#### (2) 面向对象的思维方式

&emsp;&emsp;所以我们需要换一个角度，我们将**程序关注的核心实体抽象为一个对象**，这是一个特殊类型的变量和函数的集合，它带着数据，也带着操作这些数据的方法。对象之间通过调用彼此的方法协作。
下面这个表格就是一个示例：
> [!info] 示例 | 自瞄里的面向对象方式
>以 RoboMaster 视觉任务为例，用对象的眼光看，一个自瞄系统里有很多东西：
>
>| 对象 | 它存储的数据 | 它能做的事 |
>| --- | --- | --- |
>| 相机 Camera | 照片、拍摄照片的时间戳 | 给相机输入参数、取图 |
>| 检测类 Detector | 装甲板的实际尺寸比例等 | 从图中寻找可能是装甲板的灯条 |
>| 装甲板 Armor | 四个角点、颜色、数字、中心位置 | 根据detector结果生成装甲板 |
>| ... | ... | ... |
>| 云台类 OVGimbal | 云台状态，串口 | 发送数据、接收数据、读取云台状态 |

于是整个程序就变成一句话可以描述的事：**相机取图 → 检测器找出装甲板对象 → 解算器算出它的位置 → ... → 串口把结果发出去**。每个环节只关心"调用谁、传什么、拿回什么"，可以暂时不关心对方内部怎么实现。这样就能以一个较为容易理解的逻辑将一个大项目拆分。



### 二、抽象：只关心关键信息

#### (1) 什么是抽象
创建类的时候，我们需要提取这个模块的功能和信息，这称为“抽象”。这个概念不是很好理解，我们举个例子：
&emsp;&emsp;对于一个现实中的装甲板，它有无数信息：灯条亮度、金属反光、螺丝、贴纸……但程序只关心与任务有关的那几个：四个角点、颜色、数字、中心位置。**忽略无关细节，提取关键特征和行为，这个过程就是抽象。**

抽象的结果落到代码里就是两类成员：

- **成员变量（member variable）**：它"有什么"。
- **成员函数（member function）**：它"能做什么"。

&emsp;&emsp;在代码中，我们会将我们抽象出的成员变量、成员函数组织成一个新的数据类型以代表这个东西。这个数据类型称为**类**，而用这个类型生成的变量称为**对象**。

#### (2) 类（class）与对象（object）
听上去可能有点绕，但它们其实是完全不同的两个东西：

- **类（class）**：一张设计图纸，规定了这个类型的对象"有哪些数据、有哪些功能"。图纸本身不能拿来用。
- **对象（object）**：照图纸造出来的实物。同一张图纸可以造出很多个实物，每个实物的数据互不相干。

用装甲板举例：`Armor` 是类；一帧画面里识别出的 3 块装甲板，就是 3 个 `Armor` 对象，各自有自己的角点和数字。它们在程序中应该是这样的：
```cpp
class Armor {
    // 数据成员：它"有什么"
    // 成员函数：它"能做什么"
};

// 创建对象
Armor armor1;
std::vector<Armor> armors;
```

&emsp;&emsp;对象是变量，类是类型。`Armor armor1;` 和 `int a;` 在语法地位上是一样的——`int` 是语言自带的类型，`Armor` 是我们自己定义的类型。

## part 2: 封装

### 一、访问属性修饰符
在上一个展示环节中，我们发现云台类其实被分为了两个部分，一个部分有很多成员函数，另一个则有很多变量和少量成员函数。而这两个部分开头都有一个修饰，这就是**访问属性修饰符**。
```cpp
class OVGimbal{
    public: // 这个是 public 修饰符
        void send(...);
        ...
    private: // 这个是 private 修饰符 
        struct IMUData{
            ...
        };
        ...
};
```
#### (1) 三种常见访问修饰符

| 修饰符 | 谁能访问 | 类比 |
| --- | --- | --- |
| `public` | 任何人 | 手机的屏幕和按键——给用户用的 |
| `protected` | 自己和子类 | 手机留给维修店的检测接口 |
| `private` | 只有这个类内部 | 手机内部的主板——用户不该直接碰 |

#### (2) 为什么需要访问控制？
- **分离接口和实现**：我们将给外部对象使用的方法和实现这些方法的细节分离，使得代码的阅读更加方便。了解这个类时可以只看 `public` 部分的代码来了解这个类的功能，而不需要从代码细节开始理解。这样效率更高。

- **安全性**：`private` 阻止外部代码绕过接口直接读写内部数据，降低对象被误改坏的风险。如果数据允许读取但不允许修改，可以通过 `public` 的只读接口提供，而不是把数据本身设为 `public`。


### 二、构造函数与析构函数
在上一个展示环节中，我们发现云台类中有两个特殊函数：一个和类同名，另一个在类名前多了一个 `~`，而且它们都没有返回值。
```cpp
class OVGimbal{
    public:
        explicit OVGimbal(const std::string & config_path); // 构造函数
        ~OVGimbal(); // 析构函数，对象销毁时的操作
        ...
};
```
#### (1) 构造函数：生成对象时的任务

对象被创建的那一刻自动调用，负责把对象初始化成"可用的状态"：

- **与类同名***，不指定返回值类型；
- 可以有参数，创建对象时传入：`Detector detector(config_path);`
- 如果没有声明任何构造函数，编译器会生成一个默认构造函数。它会初始化类的成员，但不会自动替你处理所有状态，内置类型成员甚至可能是未初始化的。

**读代码时的直觉**：想知道"这个类跑起来之前需要准备什么"，看构造函数就知道——要传配置文件路径？要传入图像？说明它依赖这些东西。

#### (2) 析构函数：销毁对象时的任务

对象**生命周期结束**（离开作用域、被 delete）时自动调用，负责清理。

- 名字是 `~类名()`，**无参数无返回值**；
- 如果对象管理着线程，就必须在对象销毁前让线程停止并 `join()`。否则一个仍处于可 `join` 状态的 `std::thread` 被销毁时会直接终止程序。因此，我们需要编写析构函数收尾。
- 典型工作：关闭串口

## part 3: 一些知识

### 一、函数重载

&emsp;&emsp;在 C++ 中，编译器通过一个函数的**名字+参数**去区分不同函数（**不看返回值哦**），因此允许存在多个**同名函数**，只要**参数列表不同**（个数不同或类型不同）。调用时，编译器根据你传的实参自动挑选匹配的那个。

```cpp
class Point {
    public:
        Point() : x_(0.0), y_(0.0) {} // 默认构造
        Point(double x, double y) { x_ = x; y_ = y;}
    private:
        double x_;
        double y_;
};

Point p1;            // 调用第一个
Point p2(3.0, 4.0);  // 调用第二个
```

这么设计是因为有些方法的功能近似，但是需要输入不同的参数。就比如 `ovgimbal.hpp` 中的：
```cpp
void send(const io::Command & command);
void send(const io::MPCCommand & mpc_command);
void send(bool control, bool fire, float yaw, float pitch, float yaw_vel, float yaw_acc, float pitch_vel, float pitch_acc, uint8_t armor_name_num = 0);
```

这三个方法都是向C板发送数据，但是传入的指令类型不同，在处理上会有细微的差别。

### 二、`const` 成员函数与引用参数
#### (1) const 成员函数：只读的承诺

成员函数后面加 `const`，表示"这个函数只读取成员变量，而不会修改任何成员变量"：

```cpp
double area() const;   // 算面积只看不改
```

- 对读代码的人：`const` 是一个信号——正常情况下，调用它不用担心对象状态被改变；
- 编译器会强制执行：在 `const` 函数里修改普通成员变量会直接编译报错；只有明确标记为 `mutable` 的成员可以例外；

#### (2) 引用：避免拷贝

给函数传参数时，如果不加 `&`，参数会按值传递。对于 `std::vector`、大型结构体或点云这类数据，每一次传参都可能产生一次**拷贝**，帧率就会下降。

```cpp
void process(const cv::Mat & img);  // const 引用：以只读的方式访问原对象
```

- `&` 表示传引用，函数里操作的就是原对象本身；
- 只想读不想改，就加 `const`——这是视觉代码里最高频的参数写法；
- 判断口诀：读代码看到 `const Xxx &`，理解为"借来看看，不动它"。

`cv::Mat` 的拷贝比较特殊：按值传递通常只会复制矩阵头并增加像素数据的引用计数，而不是立刻复制整张图像。不过视觉代码仍然普遍使用 `const cv::Mat &`，因为它能明确表达“只读且不修改调用者对象”的接口含义。

### 三、命名空间

当项目变大时，不同模块里可能出现相同的名字。例如，相机模块和电控模块都可能定义一个 `Command` 类型；如果这些同名类型直接放在同一个作用域中，就会造成重名冲突。**命名空间（namespace）就是给一组名字划分作用域、加上统一前缀的工具。**

我们其实一直在使用命名空间：

```cpp
std::vector<int> numbers;        // std 中的 vector
cv::Mat image;                   // OpenCV 的 cv 命名空间
io::Command command;             // 本项目的 io 命名空间
auto_aim::Shooter shooter(path); // 本项目的 auto_aim 命名空间
```

其中 `::` 叫作**作用域解析运算符**。`std::vector` 表示“`std` 命名空间里的 `vector`”，而不是另一个同名的 `vector`。这样，即使两个模块都定义了 `Command`，也可以分别写成 `io::Command` 和 `vision::Command`。

#### (1) 定义命名空间

把相关类型和函数放进 `namespace` 的一对花括号中，它们就属于这个命名空间：

```cpp
namespace auto_aim {

class Shooter {
public:
    Shooter(const std::string & config_path);
    bool shoot(const io::Command & command);
};

}  // namespace auto_aim
```

命名空间可以在多个头文件和源文件中反复打开和追加内容，因此同一个 `auto_aim` 命名空间既可以包含 `Shooter`，也可以包含 `Aimer`、`Target` 等类型。`auto_aim` 是代码中的命名空间名字，与它所在的文件夹名字没有必然联系。

需要注意，定义一个命名空间时，右花括号后不需要写分号：

```cpp
namespace auto_aim {
// ...
}  // 正确，不写分号
```

#### (2) 在命名空间外实现成员函数

如果类在头文件中声明于 `auto_aim` 命名空间，那么源文件中的成员函数也必须通过命名空间限定，或者放进同名命名空间中。

```cpp
// shooter.cpp
#include "shooter.hpp"

namespace auto_aim {

Shooter::Shooter(const std::string & config_path)
{
    // 初始化
}

bool Shooter::shoot(const io::Command & command)
{
    // 计算是否开火
}

}  // namespace auto_aim
```

也可以在定义每个函数时使用完整名字，例如 `auto_aim::Shooter::Shooter(...)`。项目里的 `ovgimbal.hpp` 和 `ovgimbal.cpp` 就是把 `OVGimbal` 放在 `io` 命名空间中，并在两个文件里都使用 `namespace io { ... }`。

#### (3) `using`：少写前缀，但不要滥用

如果某个命名空间中的名字会被频繁使用，可以用 `using` 声明省略前缀：

```cpp
#include "shooter.hpp"

using auto_aim::Shooter;

int main()
{
    Shooter shooter("config.yaml");
    return 0;
}
```

也可以直接展开整个命名空间：

```cpp
using namespace std;
```

这种方式写起来方便，但会把 `std` 中的大量名字全部引入当前作用域，容易产生重名冲突。因此：

- 初学时优先写完整的 `std::`、`cv::`、`io::`，让名字的来源更清楚；
- 在实现文件中，可以按需使用 `using std::string;` 这样的单名声明；
- **头文件中不要写 `using namespace std;`**，否则所有包含这个头文件的代码都会被迫接受这些名字，影响范围过大。

### 四、看懂一个 OOP 模块的推荐阅读顺序
1. **读头文件的 public 区**：这个模块对外提供什么功能？先建立"它能干什么"的清单。
2. **读构造函数**：它需要哪些输入（配置、依赖对象）？这告诉你这个模块"依赖谁、由谁创建"。
3. **挑一个核心成员函数读实现**：通常是和文件名相似的那个（如 `detect()`、`solve()`）。遇到调用了别的成员函数，如果细节很难读懂，那就先假设它"就是干这个名字说的事"。
4. **回到调用处看流程**：搜一下这个类在哪里被创建、在哪里被调用，把整个数据流串起来：谁创建它 → 谁调用它 → 结果给了谁。
